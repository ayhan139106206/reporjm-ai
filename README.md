# Monster-1 Persian language model

**Current status: not trained on real Persian data.** The repository currently has no approved Persian corpus, no valid 4,096-piece tokenizer, and no verified training manifest. The API therefore reports `model_ready: false` and `/v1/chat` returns HTTP 503 until a genuine from-scratch run passes the data, validation, and provenance gates.

## Architecture

Monster-1 is a small causal Transformer initialized from scratch: 4 layers, hidden size 256, 4 attention heads, 1,024-token maximum context, and 5,522,944 parameters. The target SentencePiece vocabulary is exactly 4,096. `model.py` and `config.json` define the architecture; `tokenizer.py` trains a tokenizer only from a supplied real Persian corpus and never creates fallback text.

The legacy `monster1.pt` and `monster1.onnx` files in the current GitHub history are preserved for audit/compatibility, but they are **not trained Persian model artifacts**. The checkpoint is byte-for-byte identical to the output of an earlier workflow that used a five-line synthetic corpus and random token IDs. The legacy ONNX passes graph validation and fixed-length inference, but only accepts `[1, 16]`; it is not a variable-length production model and must not be used by the API.

## Data and training

Read [DATASET_REQUIREMENTS.md](DATASET_REQUIREMENTS.md) before supplying data. The minimum planning gate is 110,458,880 actual SentencePiece tokens for training, plus 1,000,000 separate tokens each for validation and test, with source, license, attribution, rights, and checksums documented. This is a planning threshold—not a quality guarantee. No data is generated by the project.

The manually triggered `.github/workflows/monster1.yml` workflow accepts a direct HTTPS archive URL and SHA-256, downloads only that static file, checks the hash, extracts only the expected corpus files, and runs preflight. It performs no external model/API inference. Training is off by default, limited to 300 minutes, and produces a final checkpoint only after the token budget and held-out loss gates pass. Output files go to a short-retention GitHub Actions Artifact, not Git.

## API and deployment layout

`api.py` is the independent FastAPI CPU inference service. It loads `monster1.pt`, `monster1.onnx`, `monster1_tokenizer.model`, and `model_manifest.json` from `artifacts/model/` only when checksums, vocabulary, dynamic ONNX input, provenance, and completed-training metrics are valid. Run it with:

```bash
python -m pip install -r requirements.txt
uvicorn api:app --host 127.0.0.1 --port 8000
```

The Cloudflare Worker in `src/index.js` remains a gateway only. It does not run PyTorch/ONNX. Set its `MODEL_API_URL` to a separately hosted Monster-1 FastAPI service before expecting inference; without that setting, chat correctly returns 503. No paid hosting or external inference API is configured.

## Local validation

```bash
python -m unittest discover -s tests -v
python train.py preflight
```

With no corpus, preflight writes `reports/training_preflight.json`, reports the exact missing data, and does not create weights or a tokenizer. Do not describe the legacy checkpoint or the test-only ONNX fixture as a trained model.
